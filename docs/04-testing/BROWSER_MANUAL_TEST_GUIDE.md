## 📋 测试场景 1️⃣: Edit Enquiry Bug 修复

### 前置条件
- 应用已启动
- 至少存在一条 Enquiry 记录
- 浏览器缓存已清除

### 测试步骤

#### 1.1 导航到 Enquiry 列表
```
步骤:
1. 点击侧边栏 "Enquiry" 菜单
2. 查看 Enquiry 列表页面
3. 确认显示了多条记录
```

**预期结果**: ✅ Enquiry 列表正常显示

---

#### 1.2 打开现有 Enquiry 编辑表单
```
步骤:
1. 在 Enquiry 列表中，找到任意一条记录
2. 点击记录行或"编辑"按钮
3. 等待编辑表单加载

示例: 选择 Reference Number 为 "REF-2025-01-0001" 的记录
```

**预期结果**: ✅ 编辑表单打开，显示所有字段的原始值

---

#### 1.3 修改多个字段
```
步骤:
1. 在编辑表单中，修改至少 3 个字段:
   - 修改 "Commodity" 字段（新值: "修改测试商品"）
   - 修改 "Quantity" 字段（新值: 9999）
   - 修改 "Booking Confirmed" 字段（改为不同值）

2. 记录修改前的值（用于对比）
```

**预期结果**: ✅ 字段值已在表单中更新

---

#### 1.4 保存修改
```
步骤:
1. 滚动到表单底部
2. 点击 "Save" / "保存" 按钮
3. 等待保存完成（观察加载指示器消失）
4. 观察是否显示成功消息
```

**预期结果**: ✅ 显示"保存成功"消息或无错误提示

**⚠️ 如果出错**:
- 检查浏览器控制台（F12 → Console）是否有错误
- 检查网络标签（Network）中 PUT 请求的响应状态

---

#### 1.5 验证修改已保存
```
步骤:
1. 返回到 Enquiry 列表
2. 找到刚才编辑的记录
3. 再次点击编辑该记录
4. 对比各字段值是否与修改后的值一致
```

**预期结果**: ✅ 所有修改的字段值都正确显示
- Commodity = "修改测试商品"
- Quantity = 9999
- Booking Confirmed = [修改后的值]

**❌ Bug 症状（如果未修复）**:
- 打开编辑表单时，字段显示原始值（修改未保存）
- 提示错误信息

---

#### 1.6 测试其他字段修改
```
重复步骤 1.2-1.5，但修改不同的字段:

测试字段集合:
□ 修改 "Product Code"（下拉选择）
□ 修改 "Quantity SEA"（数值输入）
□ 修改 "Unit" （下拉选择）
□ 修改 "Booking Confirmed"（复选框）
□ 修改 "Remarks"（文本输入）
□ 修改 "Container Lines"（添加/删除行）

对每个字段重复保存 → 查看 → 验证流程
```

**预期结果**: ✅ 所有修改的字段都正确保存

---

## 📋 测试场景 2️⃣: Port Selection Bug 修复

### 前置条件
- 应用已启动
- 编辑表单已打开

### 测试步骤

#### 2.1 检查 POL 下拉菜单
```
步骤:
1. 在编辑表单中，找到 "Port of Loading (POL)" 字段
2. 点击下拉菜单

预期外观:
┌─────────────────────────────┐
│ Select a port...           ▼ │
└─────────────────────────────┘
  ├─ Shanghai (CNSHA)
  ├─ Shenzhen (CNSZX)
  ├─ Guangzhou (CNGZH)
  └─ ... 其他港口
```

**关键检查**:
- ❌ 不应该看到"multi-select"文本
- ❌ 不应该有多个选择框
- ✅ 应该是标准的 <select> 下拉菜单

**预期结果**: ✅ POL 是单选下拉菜单

---

#### 2.2 验证 POL 单选功能
```
步骤:
1. 点击 POL 下拉菜单
2. 选择一个港口（例如 "Shanghai"）
3. 验证只有一个港口被选中
4. 再次点击下拉菜单，试图选择第二个港口
5. 验证新港口替代了之前的选择
```

**预期结果**: ✅ 只能选择一个港口，新选择会替代旧选择

**❌ Bug 症状（如果未修复）**:
- 可以同时选择多个港口
- 显示"multi-select"文本或多选界面

---

#### 2.3 保存 POL 修改
```
步骤:
1. 修改 POL 为不同的港口
2. 滚动到表单底部
3. 点击 "Save" 按钮
4. 等待保存完成
5. 返回列表，再次打开编辑表单
```

**预期结果**: ✅ POL 值已正确保存，重新打开时显示新的港口

---

#### 2.4 检查 POD 下拉菜单
```
步骤:
1. 找到 "Port of Discharge (POD)" 字段
2. 重复步骤 2.1-2.3 的所有检查
```

**预期结果**: ✅ POD 同样是单选下拉菜单，功能正常

---

#### 2.5 测试 POL 和 POD 的独立性
```
步骤:
1. 修改 POL 为 "Shanghai"
2. 修改 POD 为 "Shenzhen"
3. 保存修改
4. 返回列表，重新打开编辑表单
5. 验证 POL 和 POD 各自保留了不同的值
```

**预期结果**: ✅ POL = Shanghai, POD = Shenzhen

---

## 📋 测试场景 3️⃣: 完整工作流测试

### 创建新 Enquiry
```
步骤:
1. 点击 "Create New Enquiry" 或 "+" 按钮
2. 填写所有必需字段:
   ✓ Enquiry Date
   ✓ Port of Loading (POL)
   ✓ Port of Discharge (POD)
   ✓ Product Code
   ✓ Commodity
   ✓ Quantity
   ✓ Etc.

3. 点击 "Save" 按钮

预期: 新 Enquiry 创建成功
```

**预期结果**: ✅ 新记录创建成功，获得 Reference Number

---

### 编辑新创建的 Enquiry
```
步骤:
1. 在列表中找到刚创建的 Enquiry
2. 点击编辑
3. 修改至少 5 个字段
4. 保存
5. 返回列表，重新打开，验证修改已保存
```

**预期结果**: ✅ 所有修改正确保存

---

### 复制现有 Enquiry
```
步骤:
1. 在列表中选择现有 Enquiry
2. 点击 "Copy" 按钮（如果可用）
3. 等待新 Enquiry 创建
4. 验证新记录有新的 Reference Number
5. 验证复制的字段值正确
```

**预期结果**: ✅ 复制成功，新记录包含源记录的数据

## 🔍 浏览器控制台检查

### 打开开发工具
```
快捷键: F12 或 Ctrl+Shift+I
```

### 检查 Console 标签
```
步骤:
1. 打开浏览器开发工具（F12）
2. 选择 "Console" 标签
3. 执行编辑和保存操作
4. 观察是否有红色错误消息
```

**预期结果**: ✅ 没有错误消息，只有普通日志

**❌ 可能的错误**:
```
❌ Failed to fetch /api/enquiries/30
❌ TypeError: Cannot read property 'id' of null
❌ SQLIntegrityConstraintViolationException: Column 'assigned_cn_office_code' cannot be null
```

---

### 检查 Network 标签
```
步骤:
1. 打开 Network 标签
2. 清除已有的网络记录
3. 执行编辑和保存操作
4. 观察网络请求

关键请求:
- GET /api/enquiries/{id} - 加载编辑表单
- PUT /api/enquiries/{id} - 保存修改
- GET /api/enquiries/{id} - 验证修改
```

**预期结果**:
- ✅ GET 200 OK（加载数据）
- ✅ PUT 200 OK（保存成功）
- ✅ GET 200 OK（验证数据）

**❌ 可能的失败**:
- ❌ PUT 400 Bad Request（数据格式错误）
- ❌ PUT 500 Internal Server Error（服务器错误）
