## 🏗️ 系统架构

LogiTrack Pro 采用前后端分离架构：

```
┌─────────────┐      ┌─────────────┐      ┌─────────────┐
│   前端UI    │ ───> │  后端API    │ ───> │   MySQL     │
│ React+Vite  │      │ Spring Boot │      │   数据库    │
│ Port: 5173  │      │ Port: 8080  │      │ Port: 3306  │
└─────────────┘      └─────────────┘      └─────────────┘
```

**技术栈：**
- **前端**: React 19 + TypeScript + Vite + Tailwind CSS
- **后端**: Spring Boot 3.2 + Java 17 + Spring Data JPA
- **数据库**: MySQL 8.0+

## 🎯 部署方式选择

### 方式一：一键自动部署（推荐新手）

适合快速体验，自动完成所有步骤。

**优点**: 简单快速，一条命令搞定  
**缺点**: 不适合自定义配置

### 方式二：分步手动部署（推荐生产）

适合需要自定义配置或学习部署流程的用户。

**优点**: 灵活可控，理解每个步骤  
**缺点**: 步骤较多

## 🚀 详细部署步骤

### 方式一：一键自动部署

#### 步骤 1: 克隆项目

```bash
# 克隆项目到本地
git clone https://github.com/dornach-Davian-Liang/LogiTrack-.git

# 进入项目目录
cd LogiTrack-
```

#### 步骤 2: 启动 MySQL 数据库

**选项 A: 使用 Docker（推荐）**

```bash
cd database
./start-mysql-docker.sh

# 等待 MySQL 启动（约 10 秒）
sleep 10

# 返回项目根目录
cd ..
```

Docker 配置：
- 容器名: `logitrack-mysql`
- 端口: `3306`
- 数据库: `logitrack`
- 用户名: `root`
- 密码: `ldf123`

**选项 B: 使用本地 MySQL**

如果已有本地 MySQL，跳过 Docker 步骤，确保 MySQL 服务已启动：

```bash
# Linux/Mac
sudo systemctl start mysql    # 或 brew services start mysql

# Windows
# 从服务管理器启动 MySQL 服务
```

#### 步骤 3: 创建数据库和导入数据

```bash
# 运行自动化部署脚本
cd database
./setup-mysql.sh
cd ..
```

这个脚本会自动：
- ✅ 检查 Python 环境
- ✅ 安装必要的 Python 包
- ✅ 创建 `logitrack` 数据库
- ✅ 执行建表脚本
- ✅ 导入 CSV 主数据

#### 步骤 4: 一键启动所有服务

```bash
# 在项目根目录执行
./start-all.sh
```

这个脚本会自动：
1. ✅ 启动 MySQL（如果未运行）
2. ✅ 构建并启动后端
3. ✅ 安装前端依赖并启动前端

### 方式二：分步手动部署

#### 第一步：准备数据库

##### 1.1 启动 MySQL 服务

**如使用 Docker:**

```bash
cd database
./start-mysql-docker.sh
```

**如使用本地 MySQL:**

```bash
# Ubuntu/Debian
sudo systemctl start mysql
sudo systemctl enable mysql

# CentOS/RHEL
sudo systemctl start mysqld
sudo systemctl enable mysqld

# macOS
brew services start mysql

# Windows
# 在"服务"中启动 MySQL 服务
```

##### 1.2 创建数据库

```bash
# 登录 MySQL
mysql -u root -p

# 输入密码后，执行以下 SQL：
CREATE DATABASE logitrack CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

# 查看数据库
SHOW DATABASES;

# 退出
exit;
```

##### 1.3 导入表结构

```bash
# 在项目根目录执行
mysql -u root -p logitrack < database/schema.sql

# 如果使用 Docker MySQL
docker exec -i logitrack-mysql mysql -uroot -pldf123 logitrack < database/schema.sql
```

##### 1.4 导入主数据（可选）

```bash
cd database

# 安装 Python 依赖
pip install mysql-connector-python pandas

# 导入 CSV 数据
python import_csv.py
```

#### 第二步：配置后端

##### 2.1 检查数据库配置

编辑 [backend/src/main/resources/application.properties](backend/src/main/resources/application.properties):

```properties
# 服务器端口
server.port=8080

# MySQL 连接配置（根据实际情况修改）
spring.datasource.url=jdbc:mysql://localhost:3306/logitrack?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
spring.datasource.username=root
spring.datasource.password=ldf123    # 修改为你的密码

# JPA 配置
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

**配置说明：**
- `localhost:3306` - 如果 MySQL 在远程服务器，修改为实际地址
- `root` / `ldf123` - 修改为你的 MySQL 用户名和密码
- `ddl-auto=update` - 自动更新表结构（开发环境）

##### 2.2 构建后端

```bash
cd backend

# 清理并构建项目
mvn clean package

# 或使用快速构建（跳过测试）
mvn clean package -DskipTests
```

构建成功后，会在 `backend/target/` 目录生成 JAR 文件。

##### 2.3 启动后端

**方式 A: 使用脚本启动（推荐）**

```bash
cd backend
chmod +x start-backend.sh
./start-backend.sh
```

**方式 B: 使用 Maven 启动**

```bash
cd backend
mvn spring-boot:run
```

**方式 C: 直接运行 JAR**

```bash
cd backend
java -jar target/logitrack-backend-1.0.0.jar
```

**启动成功标志：**
```
  .   ____          _            __ _ _
 /\\ / ___'_ __ _ _(_)_ __  __ _ \ \ \ \
( ( )\___ | '_ | '_| | '_ \/ _` | \ \ \ \
 \\/  ___)| |_)| | | | | || (_| |  ) ) ) )
  '  |____| .__|_| |_|_| |_\__, | / / / /
 =========|_|==============|___/=/_/_/_/
 :: Spring Boot ::                (v3.2.0)

...
Started LogiTrackApplication in 8.123 seconds
```

后端运行在: **http://localhost:8080**

#### 第三步：启动前端

##### 3.1 安装依赖

**打开新的终端窗口**，执行：

```bash
cd logitrack-pro

# 安装 npm 依赖（首次需要，后续可跳过）
npm install --legacy-peer-deps
```

##### 3.2 启动开发服务器

```bash
npm run dev
```

**启动成功标志：**
```
  VITE v6.2.0  ready in 823 ms

  ➜  Local:   http://localhost:3000/
  ➜  Network: use --host to expose
  ➜  press h + enter to show help
```

前端运行在: **http://localhost:3000**

## ❓ 常见问题

### 问题 1: 端口被占用

**现象：**
```
Error: Port 8080 is already in use
或
Port 5173 is already in use
```

**解决方案：**

**后端端口 8080：**
```bash
# Linux/Mac - 查找占用进程
lsof -i :8080
# 或
netstat -tuln | grep 8080

# 杀死进程
kill -9 <PID>

# Windows - 查找占用进程
netstat -ano | findstr :8080
# 杀死进程
taskkill /PID <PID> /F

# 或修改端口
# 编辑 backend/src/main/resources/application.properties
server.port=8081
```

**前端端口 5173：**
```bash
# 杀死 Node 进程
pkill -f vite

# 或修改端口
# 编辑 logitrack-pro/vite.config.ts
export default defineConfig({
  server: {
    port: 3000
  }
})
```

### 问题 2: MySQL 连接失败

**现象：**
```
com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**解决方案：**

1. **检查 MySQL 是否运行：**
```bash
# Linux
sudo systemctl status mysql

# Mac
brew services list

# Windows - 检查服务管理器

# Docker
docker ps | grep mysql
```

2. **检查连接信息：**
   - 确认 MySQL 端口是 3306
   - 确认用户名和密码正确
   - 检查 [application.properties](backend/src/main/resources/application.properties) 配置

3. **测试连接：**
```bash
mysql -h localhost -u root -p
```

4. **检查防火墙：**
```bash
# 允许 3306 端口
sudo ufw allow 3306
```

### 问题 3: 前端无法连接后端

**现象：**
```
Network Error
或
Failed to fetch
```

**解决方案：**

1. **确认后端已启动：**
```bash
curl http://localhost:8080/api/enquiries
```

2. **检查 API 地址配置：**
   
   编辑 [logitrack-pro/src/services/api.ts](logitrack-pro/src/services/api.ts) 或相关配置文件：
```typescript
const API_BASE_URL = 'http://localhost:8080/api';
```

3. **检查 CORS 配置：**
   
   确保后端允许前端的跨域请求（已在代码中配置）。

### 问题 4: Maven 构建失败

**现象：**
```
[ERROR] Failed to execute goal
或
Could not resolve dependencies
```

**解决方案：**

1. **清理 Maven 缓存：**
```bash
mvn clean
rm -rf ~/.m2/repository
mvn clean install
```

2. **检查网络连接：**
   - 确保能访问 Maven 中央仓库
   - 配置国内镜像（阿里云）

编辑 `~/.m2/settings.xml`:
```xml
<mirrors>
  <mirror>
    <id>aliyun</id>
    <mirrorOf>central</mirrorOf>
    <name>Aliyun Maven</name>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror>
</mirrors>
```

3. **使用离线模式：**
```bash
mvn clean install -o
```

### 问题 5: npm install 失败

**现象：**
```
npm ERR! network request failed
或
npm ERR! code ECONNREFUSED
```

**解决方案：**

1. **清理 npm 缓存：**
```bash
npm cache clean --force
rm -rf node_modules package-lock.json
npm install
```

2. **使用国内镜像：**
```bash
# 使用淘宝镜像
npm config set registry https://registry.npmmirror.com

# 或使用 cnpm
npm install -g cnpm --registry=https://registry.npmmirror.com
cnpm install
```

3. **检查 Node.js 版本：**
```bash
node -v
# 应该是 16 或更高版本
```

### 问题 6: 数据库导入失败

**现象：**
```
Error: Table 'logitrack.enquiry' doesn't exist
```

**解决方案：**

1. **重新导入 schema：**
```bash
mysql -u root -p logitrack < database/schema.sql
```

2. **检查数据库：**
```bash
mysql -u root -p logitrack
SHOW TABLES;
```

3. **手动创建表：**
   - 打开 [database/schema.sql](database/schema.sql)
   - 复制 SQL 语句
   - 在 MySQL 客户端中执行

## 🔧 日常运维

### 启动系统

```bash
# 方式一：一键启动（推荐）
cd /path/to/LogiTrack-
./start-all.sh

# 方式二：分别启动
# 终端 1 - 后端
cd backend
./start-backend.sh

# 终端 2 - 前端
cd logitrack-pro
npm run dev
```

### 停止系统

```bash
# 停止后端
# Ctrl+C 或
pkill -f "java.*logitrack"

# 停止前端
# Ctrl+C 或
pkill -f vite

# 停止 MySQL Docker
docker stop logitrack-mysql
```

### 重启系统

```bash
# 重启后端
cd backend
pkill -f "java.*logitrack"
./start-backend.sh

# 重启前端
cd logitrack-pro
pkill -f vite
npm run dev
```

### 查看日志

```bash
# 后端日志（如果使用 start-all.sh）
tail -f backend/backend.log

# 前端日志
tail -f /tmp/frontend.log

# MySQL Docker 日志
docker logs -f logitrack-mysql

# Spring Boot 日志（如果直接运行）
# 日志会输出到控制台
```

### 备份数据库

```bash
# 备份到 SQL 文件
mysqldump -u root -p logitrack > backup_$(date +%Y%m%d).sql

# 或使用 Docker
docker exec logitrack-mysql mysqldump -uroot -pldf123 logitrack > backup_$(date +%Y%m%d).sql
```

### 恢复数据库

```bash
# 从备份恢复
mysql -u root -p logitrack < backup_20260204.sql

# 或使用 Docker
docker exec -i logitrack-mysql mysql -uroot -pldf123 logitrack < backup_20260204.sql
```

### 更新代码

```bash
# 拉取最新代码
git pull origin main

# 重新构建后端
cd backend
mvn clean package

# 重新安装前端依赖（如有更新）
cd logitrack-pro
npm install

# 重启服务
./start-all.sh
```
